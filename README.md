# Кабинетный Навигатор

Telegram-бот для расписания учебных групп Прокопьевского филиала КузГТУ и компьютерных кабинетов из Google Таблицы.

Бот читает XLSX-экспорт таблицы, сам находит блоки по датам, пары, ФИО/события и кабинеты. Данные кэшируются, чтобы не дергать Google при каждом сообщении.

## Что умеет

- Находит группу в официальных PDF сайта Прокопьевского филиала: ВО/лицей, СПО и опубликованное расписание заочной формы.
- Присылает расписание группы на всю опубликованную неделю одним изображением с предметами, временем, днями и кабинетами.
- Под изображением даёт прямую ссылку на официальный PDF, объясняет источник и добавляет ссылку на раздел расписания.
- Показывает расписание на сегодня и завтра.
- Присылает красивую PNG-карточку расписания для одного дня.
- Показывает ближайшие даты из таблицы кнопками.
- Ищет преподавателя по фамилии или части ФИО.
- Показывает список всех преподавателей и событий.
- Обновляет данные командой `/refresh`.
- Показывает статистику пользователей кнопкой `Статистика` или командой `/stats`.
- Принимает дату текстом: `02.05.2026`.

В исходной таблице нет отдельной колонки с предметом, поэтому бот показывает номер пары и кабинет. Если в таблицу добавят предмет отдельной колонкой, парсер можно расширить.

## Расписание учебной группы

Нажми **«Расписание группы»**, выбери раздел и группу кнопкой. Также можно отправить полный код обычным сообщением или командой:

```text
ИСт-241.2
/group ИСт-241.2
/groups
/groups спо
```

Источник — [официальный раздел расписания Прокопьевского филиала КузГТУ](https://www.prk.kuzstu.ru/studentu/raspisanie/). Бот находит опубликованные документы по подписям вкладок, поэтому адрес PDF не закреплён за одной неделей. Период в подписи изображения соответствует выбранному документу. Если текущего документа нет, ближайший будущий или последний опубликованный явно обозначается; прошедшее расписание не выдаётся за текущее.

На изображениях остаются исходные пиксели PDF: бот не придумывает и не переписывает предметы. Сохраняются столбец группы, кабинеты и левая полоса с днями и временем. Совместное расписание нескольких групп сохраняет общий заголовок. Суффиксы групп и подгрупп (`.2`, `.2.1`) учитываются точно; неполный код предлагает варианты вместо выбора чужой группы.

Каталог сайта кэшируется на 5 минут, PDF — на 15 минут. Если университет заменяет PDF по прежнему адресу, перед обрезкой проверяется содержимое документа. При изменении формата или недоступности сайта бот сообщает об этом и даёт официальный источник.

Для точного чтения и рендеринга PDF используется `pypdfium2==5.15.0` (PDFium); Pillow уже используется проектом. Все нативные PDF-операции выполняются под общим lock. Столбец группы отрисовывается целиком, а продолжения на других страницах объединяются по порядку в одно изображение. Изображение проверяется по размеру файла, сумме сторон и пропорциям Telegram. Загрузка ограничена официальными HTTPS-адресами филиала, размером файлов и объёмом кэша. Vercel использует стандартную конфигурацию Python Functions с лимитом 60 секунд на webhook.

## Быстрый запуск

```bash
python -m venv .venv
.venv\Scripts\activate
pip install --require-hashes -r requirements.txt
copy .env.example .env
```

В файле `.env` укажи токен:

```env
TELEGRAM_BOT_TOKEN=123456789:your_token_here
GOOGLE_SHEET_ID=14inaoG-X5D6U3pLb1o0n3PwpZkSSlxGwoNlb6wVsU0Q
BOT_TIMEZONE=Asia/Krasnoyarsk
CACHE_MINUTES=15
WEBHOOK_SECRET=
WEBHOOK_URL=https://your-vercel-domain.vercel.app
ADMIN_USER_IDS=
USER_STATS_DB_PATH=.data/user_stats.sqlite3
UPSTASH_REDIS_REST_URL=
UPSTASH_REDIS_REST_TOKEN=
USER_STATS_KEY_PREFIX=kabinet_navigator
```

Запуск:

```bash
python -m app.bot
```

Проверка чтения таблицы без запуска Telegram:

```bash
python -m scripts.check_schedule
```

## GitHub и хостинг

GitHub нужен как репозиторий для кода. Для круглосуточной работы бота нужен worker-хостинг: VPS, Render, Railway, Fly.io или похожий сервис.

Настоящий токен нельзя коммитить в GitHub. Добавляй его в переменные окружения/Secrets хостинга как `TELEGRAM_BOT_TOKEN`.

Проект уже содержит `Procfile`:

```text
worker: python -m app.bot
```

## Запуск на Vercel

Vercel запускает не постоянный worker, а HTTP-функции. Поэтому для Vercel используется webhook:

```text
https://your-vercel-domain.vercel.app/api/webhook
```

Шаги:

1. Импортируй GitHub-репозиторий в Vercel как новый проект.
2. В Vercel добавь Environment Variables:

```env
TELEGRAM_BOT_TOKEN=123456789:your_token_here
GOOGLE_SHEET_ID=14inaoG-X5D6U3pLb1o0n3PwpZkSSlxGwoNlb6wVsU0Q
BOT_TIMEZONE=Asia/Krasnoyarsk
CACHE_MINUTES=15
WEBHOOK_SECRET=
ADMIN_USER_IDS=123456789
UPSTASH_REDIS_REST_URL=
UPSTASH_REDIS_REST_TOKEN=
USER_STATS_KEY_PREFIX=kabinet_navigator
```

Для `WEBHOOK_SECRET` сгенерируй значение и сохрани его в переменных окружения Vercel и локальном `.env`. Допускаются только латинские буквы, цифры, `_` и `-` (до 256 символов):

```bash
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

Без секрета HTTP-обработчик отклоняет запросы с кодом 503, а скрипт установки webhook останавливается. Токен бота и секрет не публикуй в сообщениях или репозитории.

3. Сделай Deploy.
4. После деплоя установи webhook из локальной папки проекта:

```bash
python -m scripts.set_webhook https://your-vercel-domain.vercel.app
```

Если потом захочешь снова запускать бота локально через polling, сначала удали webhook:

```bash
python -m scripts.delete_webhook
python -m app.bot
```

Обновить описания команд в меню Telegram без изменения webhook:

```bash
python -m scripts.set_commands
```

## Статистика пользователей

Бот показывает три показателя по уникальному Telegram `user_id`:

- **Сейчас** — обращались к боту за последние 5 минут.
- **За последние 24 часа** — обращались за скользящие 24 часа относительно момента запроса, а не с начала календарного дня.
- **Всего пользователей** — все уникальные пользователи, сохранённые с начала постоянного учёта.

Повторные сообщения и нажатия кнопок обновляют время последней активности, но не увеличивают число уникальных людей. Сообщения ботов, редактирования и служебные обновления статусов не учитываются. Для окон активности используется UTC; время в отчёте отображается в `BOT_TIMEZONE`. Telegram не сообщает боту настоящий онлайн-статус человека.

В отчёте указаны момент обновления и начало учёта активности. В первые сутки после включения нового учёта показывается предупреждение, что полные 24 часа ещё накапливаются. Историю, которая ранее не сохранялась, Telegram Bot API восстановить не позволяет.

При ошибке базы бот сообщает, что статистика временно недоступна, вместо выдачи ложных нулей. Сбой учёта активности не прерывает обработку команд.

Где смотреть статистику:

```text
Статистика
/stats
```

Строку под названием бота в поиске и шапке чата, где у популярных ботов написано `3,086,728 пользователей`, Telegram заполняет сам. Через Bot API ее нельзя выставить вручную.

Если `ADMIN_USER_IDS` пустой, команду может вызвать любой пользователь. Чтобы ограничить доступ, укажи один или несколько Telegram ID администраторов через запятую:

```env
ADMIN_USER_IDS=123456789,987654321
```

При локальном запуске или worker-хостинге статистика хранится в SQLite-файле:

```env
USER_STATS_DB_PATH=.data/user_stats.sqlite3
```

На Vercel файловая статистика не подходит для постоянного учета между перезапусками функций. Для Vercel подключи Upstash Redis и добавь переменные:

```env
UPSTASH_REDIS_REST_URL=https://...
UPSTASH_REDIS_REST_TOKEN=...
USER_STATS_KEY_PREFIX=kabinet_navigator
```

При подключении через Vercel Marketplace используются автоматически созданные `KV_REST_API_URL` и `KV_REST_API_TOKEN`; бот принимает и эту пару. Копировать или раскрывать секреты не требуется. Полная пара `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN` имеет приоритет. Данные разных пар не смешиваются.

Redis хранит общий набор пользователей и время их последнего обращения без срока истечения. Существующий общий набор пользователей сохраняется при обновлении. SQLite сохраняет старые записи в `bot_users` и продолжает учёт после повторного открытия файла.

Если Redis на Vercel не настроен, бот использует временную память процесса и явно предупреждает о сбросе и неполноте счётчиков. Для постоянной статистики база должна быть подключена к окружению **Production**.

Проверка проекта:

```bash
pip install --require-hashes -r requirements.txt
pip install -r requirements-dev.txt
python -m pytest -q
```

## Безопасность и автоматические проверки

Подробности аудита, границы защиты и обслуживание — в [SECURITY.md](SECURITY.md).

Webhook проверяет секрет до чтения тела; ограничивает размер запроса 256 КиБ и сложность JSON. Повторно доставленный успешный запрос не обрабатывается снова в том же процессе (до 4096 ID за 24 часа). Для одного пользователя доступно 20 запросов сразу с восстановлением одного запроса в секунду; уведомления о лимите отправляются не чаще раза в 5 секунд. Анонимные администраторы групп могут пользоваться командами, их лимит учитывается по группе. Эти ограничения действуют на экземпляр приложения; защиту от распределённой нагрузки обеспечивает хостинг.

Повторные `/refresh` в течение 20 секунд используют уже загруженные данные. Запрос преподавателя ограничен 120 символами. Обычные команды, кнопки и недельное расписание группы одним изображением сохранены.

Загрузки ограничены официальными HTTPS-источниками; переходы проверяются до выполнения. Перед чтением XLSX проверяются архив, XML, размеры листов и объединённых диапазонов. `defusedxml` блокирует DTD и сущности. PDF и изображения имеют лимиты размера, объектов и пикселей; нативный PDFium работает под общим lock, без отдельной песочницы процесса.

Runtime-зависимости закреплены версиями и SHA-256 в `requirements.txt`. При намеренном обновлении измени `requirements.in`, затем пересобери lock и запусти проверки:

```bash
uv pip compile requirements.in --python-version 3.12 --universal --generate-hashes --output-file requirements.txt
python -m pytest -q
python -m compileall -q app api scripts tests
python -m bandit -q -r app api scripts
python -m pip_audit --strict --require-hashes --disable-pip --progress-spinner off -r requirements.txt
```

GitHub Actions выполняет эти проверки для pull request и `main` без доступа к production-секретам. E2E-тесты используют локальный HTTP-сервер, настоящие обработчики python-telegram-bot и подмену Telegram/источников: тестовые сообщения реальным пользователям не отправляются.

## Команды бота

- `/start` - открыть меню.
- `/group ИСт-241.2` - расписание предметов и пар учебной группы.
- `/groups` - выбрать раздел и группу кнопками.
- `/yesterday` - расписание на вчера.
- `/today` - расписание на сегодня.
- `/tomorrow` - расписание на завтра.
- `/next` - ближайшие даты.
- `/date 02.05.2026` - расписание на дату.
- `/teacher Короткова` - поиск преподавателя.
- `/teachers` - список преподавателей и событий.
- `/refresh` - обновить таблицу.
- `/stats` - статистика пользователей.
